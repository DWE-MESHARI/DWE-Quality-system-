# نظام إدارة وتقييم الموظفين

نظام ويب ثابت (HTML + CSS + JavaScript) لإدارة جودة خدمة العملاء: تقييمات يومية مقسّمة بالشهر والأسبوع، لوحة تحليل شاملة، تتبع استراحات، وتقارير رسمية قابلة للطباعة. **لا يحتاج إلى خادم أو أدوات بناء.**

## الهوية البصرية
الأساس **برتقالي فاتح وأبيض**، ولكل عنصر رئيسي في النظام **لونه المميّز الخاص** ليسهل التعرّف عليه بسرعة:
- القائمة الجانبية: لوحة التحليل (برتقالي)، التقييمات (أزرق)، الإدخال الجماعي (فيروزي)، الموظفون (بنفسجي)، تقارير الموظفين (وردي)، التقرير الشهري (نيلي)، سجل النشاط (كهرماني)، الإعدادات (رمادي دافئ).
- بطاقات المؤشرات (Quality/FCR/Adherence/CSAT) بنفس الألوان في **كل** الصفحات والتقارير المطبوعة.
- مستويات الأداء: ممتاز = أخضر، جيد = أزرق، يحتاج تحسين = أحمر.
- الاستراحات: أقل من الحد = أخضر، يساوي الحد = برتقالي، يتجاوز الحد = أحمر.
- شعار النظام (درع) في صفحة الدخول وفي كل ترويسة تقرير رسمي.
- كل موظف له لون صورة رمزية مميّز من لوحة موسّعة (18 لوناً) عند إضافته.

## الميزات
| القسم | الوصف |
|---|---|
| **لوحة التحليل** | مؤشرات رئيسية، موظف الفترة، تحقيق الأهداف الفردية والجماعية، ملخص تنفيذي بنقاط القوة وفرص التحسين، رسم مسار الأداء عبر الزمن، رسم تقسيم الموظفين حسب المستوى، وجدول ترتيب. تصفية بتاريخ البداية والنهاية وباختيار موظف أو الكل، وطباعة أنيقة. |
| **التقييمات** | مقسّمة تلقائياً إلى **الشهر الأول، الثاني...** وداخل كل شهر **الأسبوع الأول إلى الرابع** (حسب يوم الشهر: 1-7 / 8-14 / 15-21 / 22 فما فوق). كل شهر يعرض بطاقة **«موظف الشهر»** (الأعلى متوسط أداء في ذلك الشهر) وزر **«تصدير الشهر»** الذي يصدّر Excel لكل الموظفين ضمن ذلك الشهر وحده. البحث باسم الموظف يفتح كل الأشهر المطابقة تلقائياً. |
| **الإدخال الجماعي** | تسجيل يوم كامل لكل الموظفين دفعة واحدة. بعد تعبئة البيانات تختارين **وجهة الحفظ**: الشهر ← الأسبوع (الأول-الرابع) ← اليوم داخل الأسبوع (1-7)، ويُحسب التاريخ الفعلي تلقائياً ويظهر معه رقم الشهر والأسبوع الناتجين. تلوين فوري لحالة الاستراحة والتحقق من صحة المدخلات. |
| **تتبع الاستراحات** | الحد المسموح يُضبط من **الإعدادات** (الافتراضي 60 دقيقة). 🟢 أقل من الحد · 🟠 يساوي الحد تماماً · 🔴 يتجاوز الحد — في كل مكان يظهر فيه وقت استراحة. |
| **تقارير الموظفين** | اختيار موظف وفترة زمنية، عرض كل التقييمات والملاحظات والاستراحات، مقارنة بمتوسط الفريق، وطباعة أو تصدير PDF. |
| **التقرير الشهري الرسمي** | تقرير للإدارة العليا: غلاف، ملخص تنفيذي، مؤشرات مقابل الأهداف، رسوم بيانية، أداء تفصيلي لكل موظف، موظف الشهر، الالتزام بالاستراحات، توصيات، وخانات توقيع. اختيار أي شهر من قائمة منسدلة. |
| **الموظفون** | إضافة/تعديل/حذف/إيقاف، بلوحة ألوان موسّعة (18 لوناً) لكل صورة رمزية، وشريط علوي ملوّن على كل بطاقة موظف. |
| **سجل النشاط والإعدادات** | سجل تدقيق كامل، وأوزان المؤشرات والأهداف وحدود المستويات وحد الاستراحة، ونسخ احتياطي JSON/Excel، وتغيير بيانات الدخول. |

## طريقة التشغيل
1. فعّلي الربط مع Supabase أولاً (قسم **"الربط مع Supabase" أدناه — إلزامي**) وأنشئي حساب المسؤول الوحيد من لوحة Supabase.
2. فك ضغط الملف.
3. افتح `index.html` في المتصفح (لا حاجة لخادم) وسجّلي الدخول بالبريد وكلمة المرور اللذين أنشأتِهما في Supabase.

> لا يوجد أي حساب أو كلمة مرور مدمجة في الشيفرة — النظام **لا يعمل دون تفعيل Supabase** أولاً. يلزم اتصال بالإنترنت دائماً لتسجيل الدخول وحفظ/مزامنة البيانات، ولمكتبات **تصدير PDF وExcel** (تُحمَّل من CDN). الرسوم والطباعة وتجميع الشهر/الأسبوع تعمل دون اتصال بعد تحميل الصفحة وتسجيل الدخول.

## الطباعة
- زر **طباعة** في لوحة التحليل وتقرير الموظف والتقرير الشهري يطبع بتنسيق A4 بنفس ألوان النظام (تُخفى القوائم وأدوات التصفية وأزرار «تصدير الشهر» تلقائياً).
- لحفظ PDF: اختر «حفظ كـ PDF» من نافذة الطباعة، وفعّل «رسومات الخلفية» إن لم تظهر الألوان.

## ملاحظات مهمة
- **التخزين محلي + سحابي:** البيانات تُحفظ فوراً في `localStorage` (فتح سريع دون انتظار)، وتُزامَن في الخلفية مع Supabase بعد تسجيل الدخول. للنقل اليدوي استخدم أيضاً *الإعدادات ← تصدير/استيراد*.
- **تسجيل الدخول حقيقي عبر Supabase Auth:** لا يوجد أي حساب أو كلمة مرور داخل الشيفرة. الحساب الوحيد (مسؤول النظام) يُنشأ من لوحة Supabase فقط، والتحقق من البريد وكلمة المرور يتم على خادم Supabase نفسه، وليس في المتصفح.
- **حماية البيانات:** كل قراءة أو كتابة في قاعدة البيانات (الموظفون، التقييمات، السجل، الإعدادات) تتطلب جلسة دخول صالحة عبر سياسات RLS في `supabase-schema.sql`. مفتاح `anon public` الظاهر في الشيفرة العلنية لا يكفي وحده للوصول إلى أي بيانات.
- **الشيفرة نفسها تبقى قابلة للقراءة:** بما أن الموقع مستضاف على GitHub Pages (استضافة ثابتة علنية)، فإن أي شخص يستطيع رؤية `index.html` / `style.css` / `script.js` كما هو حال أي موقع عام — هذا لا يمكن تجنبه في موقع ثابت، لكنه لا يعني إمكانية الوصول لحسابك أو لبياناتك، لأن كلاهما محميان عبر Supabase Auth وRLS. تعديل الشيفرة المعروضة علناً أيضاً لا يمنح أي صلاحية كتابة في قاعدة البيانات الحقيقية.
- **أسبوع الشهر يُحسب من يوم التاريخ** (1-7 / 8-14 / 15-21 / 22+)، وليس أسابيع تقويمية (أحد-سبت)، لتبسيط العرض على 4 أسابيع ثابتة لكل شهر.
- **ترقيم «الشهر الأول/الثاني»** يُحسب تلقائياً حسب أقدم شهر لديه تقييمات في بياناتك، لا حسب التقويم الفعلي.
- تُحسب **الدرجة المركبة** من أوزان المؤشرات في الإعدادات (يجب أن يساوي مجموعها 100%).

## الربط مع Supabase (إلزامي — لا يعمل تسجيل الدخول بدونه)
تسجيل الدخول والمزامنة بين الأجهزة يعتمدان بالكامل على Supabase الآن. لا يوجد حساب افتراضي ولا تسجيل ذاتي من واجهة النظام — الخطوات:

1. أنشئي مشروعاً مجانياً على [supabase.com](https://supabase.com).
2. من **SQL Editor** نفّذي ملف `supabase-schema.sql` المرفق مرة واحدة — ينشئ الجداول الأربعة (`employees`, `evaluations`, `activities`, `config`) ويفعّل سياسات الحماية (RLS) التي تمنع أي وصول بدون تسجيل دخول.
3. من **Authentication → Users** أنشئي المستخدم الوحيد (البريد الإلكتروني وكلمة المرور) الذي سيستخدمه مسؤول النظام لتسجيل الدخول. هذا هو الحساب الوحيد في النظام بالكامل.
4. من **Project Settings → API** انسخي **Project URL** و**anon public key**.
5. افتحي `supabase-config.js` وضعي القيمتين، وغيّري `SUPABASE_ENABLED` إلى `true`.
6. انشري الملفات (بما فيها `supabase-config.js` و`supabase-schema.sql`) على GitHub Pages كالمعتاد.

عند التفعيل: صفحة الدخول تطلب البريد وكلمة المرور الحقيقيين من Supabase. بعد الدخول يفتح النظام فوراً بالنسخة المحلية المخزّنة (بدون تأخير)، ثم يسحب في الخلفية أحدث نسخة من Supabase ويحدّث الشاشة إن وُجد فرق، وأي حفظ لاحق (تقييم، موظف جديد، إعدادات...) يُرفع تلقائياً لقاعدة البيانات. إن تعطّلت الشبكة مؤقتاً يستمر النظام بالعمل محلياً دون أي خطأ، لكن تسجيل الدخول نفسه يحتاج اتصالاً بالإنترنت.

**لإدارة الحساب (تغيير كلمة المرور، إلغاء الجلسات، حذف الحساب):** من لوحة Supabase فقط — **Authentication → Users**. لا توجد هذه الخيارات داخل النظام نفسه، لأن الحساب ليس جزءاً من الشيفرة أو من `localStorage`.

**ماذا يبقى علنياً وماذا أصبح محمياً:**
- *محمي بالكامل:* تسجيل الدخول (لا يمكن لأحد الدخول دون البريد وكلمة المرور الصحيحين من Supabase)، وكل البيانات في قاعدة البيانات (لا قراءة ولا كتابة بدون جلسة دخول صالحة بفعل سياسات RLS).
- *يبقى علنياً كطبيعة أي موقع ثابت مستضاف على GitHub Pages:* شيفرة الواجهة نفسها (`index.html`/`style.css`/`script.js`) قابلة للعرض لأي زائر للرابط، ومفتاح `anon public` يظهر فيها — وهذا متوقع ومصمَّم من Supabase، ولا يمنح أي وصول للبيانات أو للحساب بمفرده.
